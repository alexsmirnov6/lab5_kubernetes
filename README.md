## Запуск

Нужны Windows с работающим Docker Desktop (Linux containers), kubectl, Python и доступ в интернет для первоначальной загрузки образов. Docker должен иметь не менее четырёх CPU и достаточно памяти для двух узлов kind и RustFS; на стенде доступно 32 CPU и около 46 ГиБ. Выделенный worker оставляет для Pod 2 CPU, остальные резервируются настройкой kubelet. Скрипт вычисляет резерв по доступному числу CPU.

```powershell
cd C:\Users\Alex\Documents\inj_dan\lab5
powershell -ExecutionPolicy Bypass -File .\bootstrap.ps1
python -m unittest discover -s tests -v
python verify_results.py
```

`bootstrap.ps1` загружает kind и совместимый kubectl 1.37.0, проверяет их контрольные суммы, создаёт кластер `lab5`, собирает образ и запускает опыты. Скрипт использует `tools/kubectl.exe`, независимо от версии клиента Docker Desktop. Используются только контекст `kind-lab5` и namespace `lab5`. Уже существующее пространство имён не перезаписывается. Для повторного полного запуска сначала сохраните нужные журналы в другую папку и удалите только кластер лабораторной:

```powershell
.\tools\kind.exe delete cluster --name lab5
powershell -ExecutionPolicy Bypass -File .\bootstrap.ps1
```

Скрипт записывает применённые манифесты в `manifests/` в JSON (этот формат непосредственно поддерживает kubectl). Запускать каталог целиком через `kubectl apply -f manifests/` не следует: квота намеренно вводится после вычислений, а `quota-rejected.json` обязан завершаться отказом. Правильный порядок задаёт `run_experiments.py`.

## Как устроен расчёт

- `src/pairs.py`: локальный подсчёт, загрузка в S3, Mapper, Reducer и режим удержания ресурсов для опытов с планировщиком.
- `data/vacancies.ndjson`: подготовленные данные собственного ДЗ 3, без изменения отбора варианта.
- `reference/lab3_pairs.json`: полный эталон ДЗ 3.
- `results/pairs.json`: полный результат, скачанный из RustFS после параллельного расчёта.
- `tests/test_pairs.py`: границы диапазонов, строка длиннее 64 КиБ, отсутствие завершающего перевода строки, нормализация и полная сверка.
- `verify_results.py`: проверка сохранённых результатов и обязательных признаков каждого эксперимента; кластер не нужен.

Строка относится к диапазону, содержащему её первый байт. Незаконченная последняя строка дочитывается. Части записываются по стабильным именам `runs/parallel/part-N.json`: повторная попытка заменяет свою часть, а Reducer читает каждый индекс ровно один раз после завершения Indexed Job. Для одновременных независимых вычислений надо задавать разные `--prefix`; этот сценарий выполняет один расчёт.

Заявки CPU учитываются планировщиком даже у спящего процесса. Поэтому для демонстрации дефицита CPU и вытеснения используется `hold`, без искусственной нагрузки на компьютер. Ограничения `PriorityClass` глобальны для данного отдельного кластера. Квота действует только на `lab5`.

RustFS использует Service ClusterIP и PVC. Локальные демонстрационные ключи в манифестах относятся только к этому стенду; это не ключи предыдущих лабораторных. Перенесены сервис S3 и необходимый расчёту объект, а не всё содержимое старого бакета. Удаление kind-кластера удаляет его локальное хранилище; данные для повторения включены в проект.

## Измерения и ограничения

Пик RSS процесса и пик cgroup измеряют разные вещи: разделяемые страницы могут учитываться неодинаково. Предел контейнера выбран по `memory.peak` cgroup v2 с запасом. Значение читается перед печатью итогового сообщения. Время `elapsed_seconds` измеряет обработку, а не полную длительность Job с созданием Pod и импортом библиотек. Ускорение от четырёх Pod не заявляется.

Рабочий узел один, оба узла kind находятся на одном компьютере. PVC переживает замену Pod RustFS, но стенд не моделирует отказ физического узла. `OOMKilled`, `Pending`, `Preempted` и отказ квоты подтверждены Kubernetes, а не имитированы выводом программы.

SHA256 результатов считается по отсортированному массиву `counts`, сериализованному как UTF-8 JSON с `ensure_ascii=False, separators=(',', ':')`. Это контрольная сумма содержимого в определённом формате; она не равна SHA256 всего оформленного JSON-файла.
